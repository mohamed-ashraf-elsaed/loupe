Loupe

Privacy Policy

Last updated: October 5, 2026 · Applies to the Loupe browser extension, version 0.14.0. A site that embeds the Loupe SDK itself controls more settings; see Sites that embed the Loupe SDK.

Loupe is an open-source visual-feedback tool. It lets you inspect an element on a web page, attach a comment, and capture a screenshot or a short screen recording. It then sends that feedback to a Loupe backend that you or your organization control. This policy explains what data the extension handles and where it goes.

When Loupe runs

The extension declares no content scripts and no host permissions. It never runs on a page by itself. It enters a tab only when you do one of these:

  • Click the Loupe toolbar icon, then click Start Loupe on this tab.
  • Right-click a page and choose one of the Loupe comment items: Comment on this page, Comment on “selected text”, Comment on this image, Comment on this video, Comment on this audio, Comment on this link or Comment on this field.
  • Choose Show / hide Loupe on this page in the right-click menu on a site you hid earlier. This shows the site again and starts Loupe on that tab.

The same Show / hide Loupe on this page item works in the other direction too. On a site where Loupe is visible, it hides the site and removes the panel from the tab. While a site is hidden, the toolbar button and the comment items do nothing on it. Choose Show / hide Loupe on this page again to bring Loupe back.

Loupe also needs a project key and a user id before it starts. A project key names the Loupe project your feedback belongs to. A user id identifies you to that project. You enter both in the extension popup. If either is missing, Loupe does not start. It writes this message to the page's developer console:

[loupe] Set a project key and user in the extension popup first.

For the popup fields, see the browser extension guide and the popup fields reference.

What Loupe stores in your browser

The extension stores these values with chrome.storage. They stay in your browser:

  • projectKey: the project key you enter in the popup.
  • user: the user id and display name you enter ({id, name}). If you leave the name blank, Loupe uses "Reviewer". The popup does not ask for an email address.
  • apiBase: the API base, which is the URL of the Loupe backend that receives your feedback. It is optional.
  • userHmac: an optional signature that your own backend computes from your user id. The backend checks it to confirm that requests really come from that user. See why userHmac is computed on the server.
  • hiddenSites: the site origins you hid with Show / hide Loupe on this page, and whether each one is hidden.
  • loupeIntent: a one-time note in session storage. It holds the tool to open after you choose a right-click item, and the time you chose it. Loupe deletes it when it starts on the tab. If Loupe does not start, for example because the site is hidden or the popup is not filled in, the browser clears it when you close the browser.

While Loupe runs on a page, it also saves data in that page's own localStorage:

  • loupe:dock: panel state, such as dock position, theme, accent color, open tab, filters, sort order, launcher position and whether you finished the tour.
  • loupe:project:<project key>: project settings you change in the panel. These include the environment URLs and, if you enter them, the local AI endpoint URL and model name.
  • If you have not set an API base, your comments (loupe:<project key>:<page>), replies (loupe:msgs:*) and reactions (loupe:rxn:*).

For the full list of extension storage keys, see the storage keys reference.

What Loupe handles when you create feedback

  • Comments. Loupe builds a comment only when you leave one. It contains:
    • the title and text you type, and the priority and change type you choose;
    • your user id and display name;
    • the page path and query string, for example /checkout?step=2. A query string can contain ids or tokens;
    • the selected element's HTML, cut at 6,000 characters, and a fixed set of its computed styles, such as size, color, font and spacing;
    • the element's text (up to 120 characters), some of its attributes (role, aria-label, name, type, alt, href, placeholder, title), its position on the page, and selectors that locate it again (a CSS path, an XPath and any test id);
    • your viewport size, the Loupe SDK version, and three device facts: whether the screen is a touch screen, whether the pointer is coarse (a finger rather than a mouse), and whether the browser supports screen recording.
  • Dictation. The comment box has a microphone button. Dictation runs only when you click it, and it stops when you click it again. It uses your browser's built-in speech recognition. Some browsers send the audio to the browser vendor's speech service to turn it into text. Loupe puts the resulting text into the comment box. Loupe does not store or send the audio itself.
  • Screenshots. The extension captures the visible part of the current tab with chrome.tabs.captureVisibleTab. It then crops the image to the element or region you chose. It does not capture the full page. Any element marked data-loupe-redact is painted over in a solid color before the image leaves the page.
  • Redaction limits. Redaction applies to the image only. If you comment on an element that contains a redacted element, the HTML and text sent with the comment can still include the redacted element's content.
  • Screen recordings. Loupe records only when you use the Record tool, which captures a short video of a region you select. Recording uses your browser's standard screen-share prompt (getDisplayMedia). You choose what to share, and you can stop at any time. Recordings stop after 20 seconds. Loupe crops the video to the region you selected. Recordings have no audio. Redaction is not applied to recordings, so do not record content you do not want to share. Loupe never starts a recording on its own.
  • Files you attach. Loupe sends only files you pick yourself.

For a field-by-field explanation, see what a comment captures.

Where your data goes

The extension's background worker makes no network requests. The Loupe code that the extension adds to the tab can contact these destinations:

  • Your Loupe backend, if you set an API base. That backend is run by you or your organization. The Loupe server is open source and self-hosted. Your feedback, screenshots, recordings and attachments go there. Every request carries your user id, and your userHmac if you set one.
  • Your Loupe backend, while Loupe runs on a visible tab. Every 10 seconds, Loupe asks the backend for new comments and replies. Each request includes the page path and query string and your user id. The checks pause while the tab is hidden. While the Activity tab of the panel is on screen, Loupe also asks for the activity feed every 15 seconds.
  • No server at all, if you leave the API base empty. Feedback stays in the page's localStorage on your computer.
  • Your local AI endpoint, if you enter a local AI URL in the project settings and click Test connection. Loupe sends one request to that URL's /v1/models endpoint to list the available models. The request times out after 4 seconds.
  • Your browser's speech service, only while dictation is on. See Dictation.

Loupe's authors do not operate a shared server and never receive your data.

What Loupe does not do

  • It does not run on a tab you did not start it on.
  • It does not track your browsing history across sites. It does not use third-party analytics or advertising.
  • It does not sell or transfer your data to third parties.
  • It does not use your data for any purpose unrelated to delivering the feedback you create.

Permissions

  • activeTab: to run only on the tab you start Loupe on, and to capture a screenshot of that tab.
  • scripting: to add the feedback panel to the current page when you start Loupe.
  • storage: to remember your settings and hidden sites locally.
  • contextMenus: to add the Loupe items to the right-click menu. You use them to start a comment from what you right-clicked, or to hide Loupe on a site.

Data retention and deletion

The browser removes the extension settings and hidden sites when you uninstall the extension.

Data in a page's localStorage stays until you remove it. You can remove only Loupe's keys and keep the site's own data, such as your login. In Chrome:

  1. Open the site and press F12 to open DevTools.
  2. Click the Application tab.
  3. In the sidebar, expand Storage > Local storage and click the site's origin.
  4. Select each key that starts with loupe: and press Delete.
  5. Reload the page.

You should see the Loupe panel with its default layout and, in offline mode, no comments. Do not use Clear site data for this. It also signs you out of the site and deletes the site's own storage.

Feedback stored on your backend is controlled by you or your organization. Delete it there at any time, for example from the dashboard of the Loupe local server.

Sites that embed the Loupe SDK

A website can include the Loupe SDK directly instead of you running the extension. That site chooses the configuration, and its own privacy policy covers it. Three differences from the extension matter:

  • Screenshots are made by re-drawing the page's elements into an image, not by capturing the tab. Elements marked data-loupe-redact are left out of the image.
  • Agent bridge. If the site configures an agent bridge, Loupe sends your presence to it on a timer: the page path and query string, your user id and your name. It also keeps a live connection open to the bridge for thread updates. If the site also turns on chat, your chat messages and any screenshots you include go to the bridge. The extension never configures a bridge.
  • Code generation. If the site supplies its own code generator, Loupe passes the comment, and your local AI URL and model if you set them, to that generator.
