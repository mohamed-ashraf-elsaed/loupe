Loupe

Loupe lets a reviewer pin a comment and a screenshot to an element of a running web page. Claude Code reads the comments through an MCP (Model Context Protocol) server, the standard way for an AI agent to call outside tools. A comment stays on its element after you redeploy.

What Loupe is

Loupe is an embeddable visual-feedback platform. A reviewer opens a running product, inspects an element, pins a comment to it and captures a screenshot. The comment stays attached to that element after the markup changes. Claude Code reads the comments through the MCP server and can propose a change, which you review and resolve.

You can run Loupe in three ways:

  • The Node server. One process serves the API, the dashboard, a demo page and the SDK bundle on port 8787. It stores data in PGlite, a Postgres database that runs inside the Node process, so you need no external services.
  • The Laravel package. loupekit/laravel stores comments in your app's database and gates access with your app's users.
  • Offline mode. Without a backend, the widget stores comments in the browser's localStorage only.

The packages

shared

Contract layer

Canonical types, stages and normalizeUrl(). Every package imports from here.

sdk

The widget

Runs in a Shadow DOM, an isolated DOM tree, so your page CSS does not change it. Inspect, comment, capture, record, re-anchor.

server

The API

node:http, Postgres, blob storage, signed-user auth and static hosting.

dashboard

Triage board

A five-stage board for people, with filters and saved views.

mcp

For Claude

MCP server that gives Claude Code 19 tools over your comments.

extension

Any site

Chrome extension in Manifest V3 (MV3), the current Chrome extension format. It runs the SDK core on any page you open.

hub

Loupe Hub

Optional server that routes tickets between the apps of one organization.

laravel

Loupe for Laravel

Composer package: widget, your database, gates, dashboard and MCP.

The feedback loop

  1. A reviewer pins a comment on the live page. It lands in the Queue stage.
  2. Someone triages it on the dashboard and moves it to To Do.
  3. Claude Code reads it over MCP, works on it, and moves it to In Review.
  4. A person checks the result and moves it to Resolved.
Rule

An agent may move a comment to In Review. Only a person resolves it.

Tutorial

Quick start

In this five-minute run you start the local server, pin a comment on the demo page and see it on the dashboard. For the full walk-through, including Claude Code, follow the tutorial Pin your first comment locally.

Prerequisites

  • Node 24. Run node --version. You should see v24.
  • Git and a terminal.

Steps

  1. Clone the repository and install the dependencies:
    bash
    git clone https://github.com/mohamed-ashraf-elsaed/loupe.git
cd loupe
npm install
  2. Build the packages:
    bash
    npm run build

    You should see the packages build in the order shared, sdk, mcp, dashboard, extension.

  3. Create the demo project:
    bash
    npm run seed

    You should see these first two lines:

    output
    Seeded project: pk_demo_acme
  admin key   (dashboard ?key= / X-Loupe-Admin): sk_demo_acme_0f3b9c

    A third line prints the demo user's HMAC. Two values identify a project:

    • The project key (pk_demo_acme) names the project. It is public, so you can put it in a page.
    • The project secret (sk_demo_acme_0f3b9c) is private. The seed output calls it the admin key, because the dashboard ?key= parameter and the X-Loupe-Admin header take it. This page calls it the project secret.
  4. Start the server:
    bash
    npm start

    You should see [loupe] API + static on http://localhost:8787 (dashboard: /dashboard/ · demo: /demo/). Leave this terminal running.

  5. Open http://localhost:8787/demo/. You should see the demo page with the Loupe panel open and a short tour.

  6. In the panel, click Inspect. You should see the pointer outline elements as you move it.
  7. Click the Send invite button on the demo page. You should see the composer open next to the button.
  8. Type a title and a description. You should see the Comment button turn active.
  9. Click Comment. You should see a numbered pin on the button.

  10. Open the dashboard at http://localhost:8787/dashboard/?key=sk_demo_acme_0f3b9c. You should see your comment as a card in the Queue column.

Troubleshooting

SymptomCauseFix
The build or start fails with a syntax error.Node is older than 24.Install Node 24 and run npm install again.
The dashboard answers 401.The key is not the project secret.Use sk_demo_acme_0f3b9c after npm run seed.
The demo page cannot load or save comments, and requests answer 401.LOUPE_DEMO_SECRET was set when you ran npm run seed. The demo page has a fixed HMAC for the default secret.Stop npm start. Run unset LOUPE_DEMO_SECRET, then npm run seed, then npm start, and reload the page.
npm start fails because the port is in use.Another process holds port 8787.Stop it, or set PORT to a free port.

How-to

Install

Pick the procedure that fits your app. Each procedure here covers the common path. For every option and more troubleshooting, follow the Full guide link at the end of the procedure.

Script tag

Prerequisites:

  • A page you can edit.
  • A running Loupe backend, such as the local server from the Quick start, or no backend for offline mode.
  • A project key and a project secret. The Node server has no route that creates a project: npm run seed creates or updates the project pk_demo_acme, and LOUPE_DEMO_SECRET, if you set it before you seed, chooses its secret.
  1. On your server, compute the user's HMAC. An HMAC here is a SHA-256 keyed hash of the user id, made with the project secret. It proves that your server vouches for the user, and the browser never sees the secret. To try it from a terminal, run:
    bash
    node -e 'console.log(require("node:crypto").createHmac("sha256", "<PROJECT_SECRET>").update("<USER_ID>").digest("hex"))'

    Replace <PROJECT_SECRET> with the project secret and <USER_ID> with the signed-in user's id. With sk_demo_acme_0f3b9c and u_92, you should see decb2c23961bbcea494b1034aad995b8f30c9a2e517598667b791b73e8752846. In your app, run the same createHmac call on each request and put the result in the page.

  2. Add the browser build before </body>. Pin the exact version:
    html
    <script src="https://cdn.jsdelivr.net/npm/@loupekit/sdk@0.14.2/dist/index.global.js"></script>
<script>
  Loupe.init({
    projectKey: "<PROJECT_KEY>",
    user: { id: "<USER_ID>", name: "<USER_NAME>", email: "<USER_EMAIL>" },
    userHmac: "<USER_HMAC>",
    apiBase: "<API_URL>",
  });
</script>

    Replace <PROJECT_KEY> with your project key, for example pk_demo_acme. Replace the user fields with the signed-in user, for example sara@acme.com. <USER_HMAC> is the value from step 1. <API_URL> is your backend, for example http://localhost:8787. Leave apiBase out to run in offline mode.

  3. Load the page. You should see the Loupe panel open, docked on the right. On a screen wider than 640 px, the first-run tour starts.

Troubleshooting:

SymptomCauseFix
Nothing appears, and the console shows [loupe] init requires a projectKey or [loupe] init requires user.id.The option is missing or empty.Pass projectKey and user.id.
The panel opens, but comments do not load, and requests answer 401.userHmac was not made with this project's secret and this user id.Compute it again as in step 1.

npm

Prerequisites: a browser app built with npm, and the project key, HMAC and backend URL described in Script tag.

  1. Install the package:
    bash
    npm i @loupekit/sdk

    You should see @loupekit/sdk added to dependencies in your package.json.

  2. Call init once, in the browser only:
    ts
    import { init } from "@loupekit/sdk";

init({
  projectKey: "<PROJECT_KEY>",
  user: { id: "<USER_ID>", name: "<USER_NAME>" },
  userHmac: "<USER_HMAC>", // computed on your server
  apiBase: "<API_URL>",   // omit for offline mode
});
  3. Start your app and open it in a browser. You should see the Loupe panel open, docked on the right.

Framework notes: the widget needs document, so call init once where your app starts. The SDK has no React, Vue or Svelte adapter. In React, call it in an effect in your root component and return destroy as the cleanup. In Vue 3, call it in onMounted and call destroy in onBeforeUnmount. You need no router hook: the SDK follows history changes.

Troubleshooting:

SymptomCauseFix
ReferenceError: document is not defined during server-side rendering.init ran on the server.Call it in a browser-only hook, such as a React effect or Vue onMounted.
Nothing appears, and the console shows [loupe] init requires a projectKey.projectKey is missing.Pass it.

Laravel

Prerequisites: a Laravel 11, 12 or 13 app on PHP 8.2 or later (Laravel 13 needs PHP 8.3), with a way for users to sign in. The installer warns you when the app has no login route.

  1. Require the package:
    bash
    composer require loupekit/laravel
  2. Run the installer:
    bash
    php artisan loupe:install

    You should see Loupe installed. Next steps:. The installer publishes the config, the migrations, the assets and app/Providers/LoupeServiceProvider.php.

  3. Create the tables:
    bash
    php artisan migrate
  4. Add @loupeWidget just before </body> in your layout.
  5. With APP_ENV=local, sign in and load a page. You should see the Loupe panel. This works only in the local environment, where allow_in_local lets every signed-in user in. In every other environment the default gates deny everyone.
  6. Grant access outside local. In app/Providers/LoupeServiceProvider.php, list the people in the two gates:
    php
    Gate::define('loupe:use', function ($user) {
    return in_array($user->email, ['sara@acme.com']);
});

Gate::define('loupe:admin', function ($user) {
    return in_array($user->email, ['sara@acme.com']);
});

    loupe:use shows the widget. loupe:admin opens the dashboard at /loupe/dashboard.

  7. Deploy, then sign in as a listed user. You should see the Loupe panel.

Troubleshooting:

SymptomCauseFix
The widget does not appear.You are not signed in, you fail loupe:use, LOUPE_ENABLED is false, or the assets are not published.Sign in, add your email to loupe:use (step 6), check .env, and run php artisan vendor:publish --tag=loupe-assets --force.
The dashboard answers 403.Outside local, your user fails loupe:admin.Add your email to loupe:admin (step 6).

MCP server

Prerequisites: Claude Code, Node 24, a running Loupe backend, and the project key and project secret.

  1. Create .mcp.json in the root of the project you open in Claude Code:
    json
    {
  "mcpServers": {
    "loupe": {
      "command": "npx",
      "args": ["-y", "@loupekit/mcp"],
      "env": {
        "LOUPE_API": "<API_URL>",
        "LOUPE_PROJECT_KEY": "<PROJECT_KEY>",
        "LOUPE_ADMIN_KEY": "<PROJECT_SECRET>"
      }
    }
  }
}

    <API_URL> is your backend, for example http://localhost:8787. <PROJECT_SECRET> is the project secret, for example sk_demo_acme_0f3b9c. Keep the file out of version control if it holds a real secret.

  2. Restart Claude Code and run /mcp. You should see loupe listed.
Fixed in 0.14.1

The published @loupekit/mcp 0.14.0 fails at start with ERR_MODULE_NOT_FOUND. On 0.14.0, run the server from a clone: set "command": "node" and "args": ["<ABSOLUTE_PATH_TO_CLONE>/packages/mcp/index.ts"], after npm install and npm run build:shared in the clone.

How-to

Using the widget

These are the key tasks. The widget guide covers every control.

Open and close the panel

  1. The panel starts open the first time a page loads Loupe. To close it, click the Close button in the panel header. You should see the round launcher in the corner of the page.
  2. Click the launcher. You should see the panel open again.

The launcher has a menu with the main tools:

Press Alt+Shift+L to hide or show the launcher. The shortcut does not open the panel.

On the first load on a screen wider than 640 px, a five-step tour starts. You can restart it later with Restart tour in the panel settings menu.

Comment on an element

  1. Click Inspect and hover the page. You should see the element under the pointer outlined, with a tip that names it.

  2. Click the element. The composer opens next to it. Type a one-line title and a description. Optional: choose a priority (default Medium) and a change type (default Other). You can attach up to 10 files: each image up to 10 MB and each video up to 25 MB.

  3. Click Comment. You should see a numbered pin on the element. New comments start in the Queue stage.

Comment on a region

  1. Click Region. You should see the pointer change to a crosshair for a drag.
  2. Drag a rectangle over the area. You should see the composer open next to it.
  3. Type a title and a description, then click Comment. You should see a numbered pin on the region. Loupe anchors the region to the smallest element that covers at least 60% of it, so the region follows a responsive reflow.

Record a short video

  1. Click Record.
  2. Drag a rectangle over the area to record. You should see the browser's screen-share prompt.
  3. Pick what to share. You should see the recording bar with a Stop button.
  4. Click Stop when you finish. A recording stops by itself after 20 seconds. You should see the composer open with the video attached.

Screen recording works only in desktop browsers. On a phone, the panel shows a Video button instead, which attaches a clip you recorded with the phone's own screen recorder.

To keep sensitive content out of captures, add data-loupe-redact to the element. Loupe paints it over before the image leaves the browser.

Reply, resolve or delete

  1. Open a comment in the Comments list. You should see the screenshot, the conversation and a reply box. Type @ to mention someone.
  2. Click Resolve to close it, or Reopen to bring it back.
  3. Click Delete. The comment is deleted at once, with no confirmation. In the Laravel package, only the author or an admin can delete.

Find comments

The Comments tab lists the comments on the page. Use the search box, the status filter and the sort order (newest first, oldest first, or page order). On This page the default order is page order; on All it is newest first. When the list is sorted by date, it is grouped by day: click a day header to fold that day.

Use the Home tab

Home shows what needs you: tiles such as Needs you and Stale, and a Recent list where each row has Resolve (or Reopen), Open and Delete buttons. On a Home row, Delete asks once: click it, then click Confirm delete within 3 seconds.

Move and style the panel

Dock the panel to the side or let it float, and pick an accent color in Settings.

To hide the launcher from code, call hideLauncher(); call showLauncher() to bring it back.

Switch environments

When you pass the environments option, the project popover lets reviewers jump between environments of the same project.

Watch agent activity

The Activity tab shows events from two sources: the backend's activity feed (GET /v1/activity), and events that your page sends with Loupe.trackActivity({ kind, label }), together with Loupe's own operations in this browser. The Laravel package serves the feed, so the tab shows No activity yet until something happens. The Node server has no activity feed, so with no local events the tab shows Monitor unavailable, whether or not the MCP server runs.

Answer a navigation request

An agent can ask to open another page. The widget asks you first: click Go there or Stay here.

Use Loupe on a phone

The panel adapts to small screens.

How the panel stays current

The panel re-reads comments, open threads and mentions every 10 seconds. It pauses while the tab is hidden and skips a read while you type.

Dashboard

The dashboard is the triage board for people. On the local server, open /dashboard/?key=<PROJECT_SECRET>, where <PROJECT_SECRET> is the project secret.

Five stages

StageMeaning
QueueNew, not triaged yet. Every new comment starts here.
To DoTriaged and accepted.
In ProgressSomeone or something is working on it.
In ReviewA change is ready and waits for a person.
ResolvedA person accepted the change.

Move a card to another stage

Prerequisites: the dashboard is open with the project secret.

  1. Click a card. You should see its details, with ‹ and › buttons.

  2. Click › (Move forward) to move the card to the next stage, or ‹ (Move back) to move it to the previous one. You should see the card in the new column.

To delete a card, click Delete, then Confirm? within 3 seconds.

Filters and saved views

Narrow the board with the search box (title, text, author) and the filters for page, repo, branch, kind, device, priority and change type. Change the order with the sort menu.

The view menu has four saved views: All feedback, Needs you (In Review), Critical only and Not linked to a repo.

Live refresh

The board reloads every 4 seconds, so cards move as people and agents work.

Integrations and Connect Claude

The Integrations page sends lifecycle events to Slack or Telegram. The Connect Claude page shows a ready-to-copy MCP configuration with your API URL and project key.

Loupe for Laravel

loupekit/laravel puts the whole loop inside a Laravel app: the widget, your database, your users, a dashboard and an MCP server. It needs PHP ^8.2 and Laravel 11, 12 or 13 (Laravel 13 needs PHP 8.3 or later). Install it with the Laravel procedure.

Authorization order

The package checks access in this order and stops at the first answer:

  1. No signed-in user: deny.
  2. A closure in config('loupe.authorize.use') or config('loupe.authorize.dashboard'): its answer.
  3. A closure registered with Loupe::useWhen() or Loupe::adminWhen(): its answer.
  4. allow_in_local is true and the environment is local: allow.
  5. The loupe:use or loupe:admin gate: its answer.

Explanation and how-to

Loupe Hub

Hub is an optional, separate server that moves a comment from the app where it was written to the app that should handle it. It routes only between apps of the same organization, and it does not store tickets.

Concepts

TermMeaning
OrganizationHolds members, an optional allowed email domain, and projects.
Owner / memberOwners change everything. Members view and submit.
ProjectOne connected app, with a Hub project secret (psk_) and a webhook signing secret (whs_). The Hub project secret is not the Loupe project secret.
Inbound URLWhere a project receives tickets, for example https://tracker.example.com/loupe/v1/hub/inbound.
DestinationThe project that a project's tickets go to.

Start Hub and create a project

Prerequisites: a clone with npm install done, and a Google OAuth client id. Without GOOGLE_CLIENT_ID, the sign-in page says it is not configured and sign-in answers 503.

  1. Start Hub with your client id:
    bash
    GOOGLE_CLIENT_ID=<GOOGLE_CLIENT_ID> npm run start:hub

    <GOOGLE_CLIENT_ID> is the client id of your Google OAuth client. You should see [hub] Loupe Hub on http://127.0.0.1:8790.

  2. Open http://127.0.0.1:8790/ and sign in with Google. You should see the Organizations page.

  3. Type a name, for example Acme, and click Create. You should see the new organization in the list.

  4. Open the organization. You should see its members and projects.

  5. Type a project name, for example Tracker, and click Create project. You should see the project page with the card Copy now. These secrets are shown only once. Hub shows the secrets only when it creates or rotates them, so copy them now.

  6. Go back to the organization and open the project. You should see the project page without the secrets.

To run Hub for others, set HUB_SESSION_SECRET (required when NODE_ENV=production). See Self-host Hub.

Routing

Hub checks the signature, the body and the submitter, then picks the first route that applies:

  1. Destination project. If the project has a destination with an inbound URL, Hub delivers there, signed with the destination's secret and the X-Loupe-Hub-Project header.
  2. Webhook fallback. Otherwise, if the project has a webhook URL, Hub delivers there, signed with the webhook signing secret.
  3. Nowhere. Otherwise Hub answers 202 {id, delivery: "none"}.

Two-way sync

After a project-to-project delivery, both apps hold the ticket. The receiving app owns the status: when it changes there, the sender's card moves to the same stage and its chip shows the remote state, for example → Tracker · TCK-42 · In progress. Replies travel both ways. A ticket sent to an external webhook is one-way and cannot receive updates.

Security summary

  • Every request in both directions is signed with HMAC-SHA256 over <timestamp>.<raw body>. Timestamps more than 300 seconds off are refused.
  • Hub stores secrets in plain text, because it must sign with them. Protect its database.
  • Dashboard sign-in uses Google with a verified email; the hub_session cookie is HttpOnly; Secure; SameSite=Lax.
  • 0.14.1 Hub refuses to deliver to private, loopback and link-local addresses. HUB_ALLOW_PRIVATE_URLS=1 turns this off, for local development only.
  • 0.14.1 A reply URL is kept only when its path ends in /v1/hub/inbound and it has no credentials. When the sending project has an inbound URL registered, the reply URL must also have the same origin as that inbound URL.

The two items marked 0.14.1 are not in Hub 0.14.0 or earlier.

Re-anchoring

Each pin stores a fingerprint, a set of properties that identify its element: tag, CSS path, XPath, test id, text, attributes and position. On every load, a unique test id or id wins at a score of 0.98. A CSS path rooted at a stable id wins at 0.90. Otherwise Loupe scores candidates: the elements at the stored CSS path and XPath, every element with the same tag, and, when the pin has text, elements with the same text, a scan that stops at 4,000 candidates. Below 0.5, the pin detaches and shows "moved" instead of pinning to the wrong element. Give important elements a data-testid. A region anchors to the smallest ancestor that covers at least 60% of it.

Authentication

The Node server accepts an admin (the X-Loupe-Admin header equals the project secret) or a user (the X-Loupe-Hmac header equals HMAC-SHA256 of the user id with the project secret). Your server computes the HMAC, so the browser never sees the secret. The Laravel package uses the session and its gates instead. See Authentication and privacy.

URL normalization

normalizeUrl keeps the path and query, drops tracking parameters such as utm_*, gclid and fbclid, sorts the rest and removes one trailing slash. So /checkout?utm_source=x and /checkout share one set of comments.

Screenshots and storage

The SDK uploads each capture to POST /v1/blobs and stores only the returned URL. The server keeps blobs under LOUPE_BLOB_DIR; the Laravel package uses a filesystem disk.

Seams

You can replace request headers and credentials, capture functions, panel tabs, the generate function, integration providers, the database (DATABASE_URL), and, in Laravel, the event listeners and resolvers. The SDK picks its storage itself: the HTTP adapter when you pass apiBase, localStorage otherwise. The storage adapter is an internal interface, not an option.

Data model

The Node server stores projects, comments, thread messages, thread participants, reactions, notifications, working branches, repo URLs, integrations, integration mappings and integration deliveries. The Laravel package uses loupe_comments, loupe_messages, loupe_reactions, loupe_notifications and loupe_activity.
