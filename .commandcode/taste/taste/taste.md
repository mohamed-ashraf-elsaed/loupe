# Taste
- Wants a plan shown first and explicit approval gates before any destructive or billable action (creating GCP projects/VMs/firewalls, deploying). Never proceed on costed/resource-creating steps without a "yes". Confidence: 0.9
- Explicitly instructs: do not commit, tag, bump versions, or publish without asking. Confidence: 0.9
- Prefers answering clarifying questions up front in a single batch (one round of AskUserQuestion) before any code is written. Confidence: 0.7

Don't assume he already performed a manual step ("i didnt do any thing in this issue give me the steps to fix"). When a process doc (e.g. RELEASING.md) has manual steps, pull the still-remaining ones out and list them inline in chat as an actionable checklist/table ("give me the manual steps here") rather than pointing him at the doc to read. Confidence: 0.75
- Strong MVP minimalism: build only the requested features, no extras (no billing, analytics, styling frameworks), server-rendered HTML is fine. Confidence: 0.9
- Pushes back on non-essential additions and drops undo/backup/rotation extras for an MVP (e.g. "no backups now, this is only MVP"). Confidence: 0.8
- Follow the existing monorepo/package patterns and style; reuse existing seams (db.ts, auth.ts) instead of inventing new structure. Confidence: 0.8
- Prefer no new dependencies unless necessary; allow only the minimum needed. Confidence: 0.7
